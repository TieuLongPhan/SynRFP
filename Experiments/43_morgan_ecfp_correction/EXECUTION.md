# Corrected Morgan operational execution

This scheduler does not alter scientific code, original caches, weights, previous
experiments, the corrected package, or device drivers. The separate scientific
protocol fixes 216 corrected feature pools, 1,680 MLP classification fits and
1,440 clustering fits. Forty-eight original WL/Path configurations remain fixed
historical controls. The controller does not call their results corrected Morgan.

The root is `~/.local/share/synrfp-runs/morgan_ecfp_correction_v1`. Control records
are isolated under `control/`. Start requires tested scientific/core/controller
readiness, the actual CPU encoding/clustering/initialization pilot, and an exact
root review. Root review schema `morgan43-root-reviewed-v1`, phase `reviewed`,
binds `plan_sha256`, `core_ready_sha256`, `science_code_ready_sha256`,
`controller_code_ready_sha256`, `pilot_receipt_sha256`, the union
`sources_sha256`, and `stages_allowed: [encode, clustering, mlp]`. Scientific
workers independently verify the review and retain model/prediction replay.

One encoder has six CPU equivalents/16 GiB, cores 8–13 and four child encoder
processes; two clustering workers each have four CPU equivalents/12 GiB, cores
14–17 and20–23. One MLP worker has two CPU equivalents/16 GiB, cores24–25 and
physical GPU1. MLP admission requires the original T5 ticket002 to be complete,
its exact native_seed43 native closure and nested artifact hashes to verify,
the attested original owner service to be inactive with zero MainPID, and the
existing original GPU1 lease to be free. The worker acquires that same original
lease. GPU0 is never admitted. NVML diagnostic failures do not authorize driver
changes or imply a failed PyTorch execution.

All finite research cgroups count toward the new85% aggregate ceiling. Sealed
42resource85 and39persistence helpers are imported under isolated module names.
Original75% controllers remain unchanged. While41 priority remains active,
its pending native/comparison memory reservations and additional2CPU/4GiB
concurrent-reference headroom are preserved. Scheduling is independent by lane:
a resource wait is pending work, not a scientific failure. New cgroups must be
visible with their exact quota/RAM reservation before another admission.

RAM cooperative yield starts below30% global available memory with35% recovery
while41 is active, or15%/20% after verified41 completion/quiescence. BothHOME
and resolved artifact filesystems retain the hard40GiB floor. Study43 uses
42/43GiB disk yield/recovery rather than the older44/48GiB thresholds: retained
new canonical outputs would otherwise prevent recovery forever. Signals affect
only attested43 main PIDs whose STARTED record belongs to the current run/PID;
SIGUSR1 finishes the current scientific item and retains all artifacts. There
are no automatic freezes, worker kills, other-study signals, lease replacements,
old-file deletions, or driver mutations.

Every invocation has a fresh generation ID. Completed/yielded outputs are checked
against exact planned shard keys and native nested artifact catalogs. An inactive
interrupted invocation is preserved, classified and followed by a new generation
after30seconds. Three failed generations or a recognized integrity/CUDA/OOM/import
failure latch that lane; no old invocation directory is restarted. Source drift
stops new work and requests cooperative yield only from owned43 workers. The
original35/42 governors must remain inactive. The scheduler never resumes42.

`control/WORKERS_COMPLETE.json` closes verified native workers only; the separate
publication report is not asserted complete here. Controller preparation is
`python controller.py --preflight`; production installation/enabling is performed
only by root after independent review. Copy the supplied service into the user
unit directory, daemon-reload, then enable/start `synrfp-morgan43-v1.service` after
writing the concrete review. No production action is part of preflight.

The CPU encoder, clustering and final report run in the original `synrfp`
interpreter. MLP parent/child execution remains in the original `synprop`
interpreter. `ENVIRONMENT_READY.json` pins their versions/backend files, the
new CPU-environment pilot and the preserved original MLP-initialization pilot.
This avoids silently selecting a different MinHash fallback. Root review also
binds `environment_ready_sha256`, `report_code_ready_sha256`, and
`reference_resume_ready_sha256`; the latter authorizes only the previously
enabled/active35 governor identified by its unchanged installed unit SHA.

Once features and the GPU handoff are ready, MLP admission is considered before
other43 lanes. If an otherwise admissible MLP is blocked by live43 CPU workers,
only the minimum attested43 CPU workers needed to admit it are asked to yield at
an item boundary; no replacement CPU generation starts ahead of that request.
Existing41 scientific work retains priority throughout.

After all1680 MLP outputs close and every owned MLP unit is inactive with zero
PID, the existing GPU1 lease must be free and resources must admit the exact
0.1CPU/256MiB reference governor. An immutable restore intent precedes the
reviewed `systemctl --user enable --now` action; exact installed unit bytes,
ExecStart, environment, finite caps and actual visible cgroup are attested. A

All scientific workers must be inactive before the final2CPU/8GiB report runs.
The report uses fresh generations for interrupted retries and closes only the
exact plan/profile and two task catalogs. Even after report completion the
controller keeps polling until the authorized reference handback is complete.
