# Morgan guardian recovery

The original Path reporting attempt failed at16:07UTC when systemd had garbage
collected its transient report unit. During the Path governor's30-second restart
delay, systemd listed it as activating/auto-restart withPID0 and no cgroup. The
old resource auditor interpreted that absent group as the cgroup root, then
latched Morgan's guardian. Both preserved failure receipts remain historical.
Scientific workers continued; all1680 MLP cells subsequently finished.

This new operational version preserves the original43 scientific source, plan,
dispatches, lock, model weights, failure records and physical GPU leases. Its
resource adapter counts configured finite CPU/RAM caps during only a proven
loaded/activating/auto-restart/PID0/empty-cgroup interval. A real live process
without its named finite cgroup still fails closed. Other disappearing-service
races receive a bounded retry, never an unconditional omission.

The recovery review binds the exact prior failure and original execution. The
guardian reuses original MLP shard/PID/lease checks before restoring specialist35,
continues clustering supervision and dispatches the original full report. It
does not signal or restart an existing scientific worker. It uses the original
controller lock and a new control_recovery_v3 namespace.

A separately persistent coordinator waits for both complete native43/44 reports,
all43/44 science/report services and the recovered43 guardian to exit. It then
uses the original attested governor-only41 restore, retaining shared admission.
It never treats an idle GPU, a cell count or a prepared report as full closure.
