# Default and task-optimal SynRFP benchmark arms

The user requests two SynRFP entries in every seven-task benchmark. `SynRFP
(default)` retains the existing shared experimental reference: WL/r2/parity/
delta/2048, fingerprint seed1. This does not change the public library default.
`SynRFP (task-optimal)` uses one construction per task across all its datasets,
selected from the completed, corrected, full-cohort study56 factorial.

Selection uses the existing grouped_main task view, ascending source-family
balanced mean rank, then normalized regret, then configuration ID. Reagent and
condition use their grouped view for selection; the same selected construction
is subsequently evaluated on their separately labelled native panels. This
preserves source-family weights, never pools barrier units, and prevents a new
per-dataset winner from being chosen. The classification construction is chosen
with MLP MCC and transferred to kNN; it is not claimed to be the kNN optimum.
Selections and all resulting benchmarks are exploratory after viewed outcomes.
Known-K and class-count-blind clustering remain distinct tables.

Existing default results, baselines, native learners, full eligible rows, split
arrays, train order and repetitions are retained. Study52 main replacements
supersede only their exact keys. Yield uses corrected full NCS and literal-source
USPTO inputs, preserving the study57 information boundary for three invalid
source records. The yield-optimal construction transfers to USPTO without a
claim that a USPTO factorial has run. Historical NCS subsets remain historical.

Compatible optimal results are reused with explicit origins. Missing main fits
are queued separately; classification preserves both learners and all25 saved
folds, rather than substituting its five-fold factorial MLPs. The corrected
TPL known-K shared population is445043, requiring new Path comparisons there.
No missing cells are filled with a different learner, population or split.

All scientific inputs, decisions and producer sources are hash-bound. A task's
table is partial until every default and optimal key is present. Metadata,
metrics and provenance may be exported; weights and heavy arrays stay local.
Existing scientific workers, frozen sources and physical GPU lease files are
preserved. New GPU1 work waits for the higher-priority matched FP55 comparison;
CPU/GPU admission retains existing CPU85/RAM90 ceilings and native40 headroom.
